## 零、 前置准备：数据库初始化、模型配置与工程启动

### 1. 数据库就绪（区分全新建库与存量升级）
- **情况 A：全新空库初始化**  
  [tables_xxl_ai.sql](../doc/db/tables_xxl_ai.sql) 已完整包含全部 16 张表结构（含 `xxl_ai_agent` 扩展列、`xxl_ai_eval_*`、`xxl_ai_workflow*`）与种子数据：
  ```bash
  mysql --default-character-set=utf8mb4 -h127.0.0.1 -P3306 -uroot -p123456 < doc/db/tables_xxl_ai.sql
  ```
- **情况 B：基于旧库增量升级**  
  若本地已存在旧版 `xxl_ai` 库，请按顺序补充执行全部补丁（务必携带 `--default-character-set=utf8mb4` 避免中文注释与提示词乱码）：
  ```bash
  mysql --default-character-set=utf8mb4 -h127.0.0.1 -P3306 -uroot -p123456 xxl_ai < doc/db/patch_20261110_p2_agent_options.sql
  mysql --default-character-set=utf8mb4 -h127.0.0.1 -P3306 -uroot -p123456 xxl_ai < doc/db/patch_20261110_p3_agent_subagent.sql
  mysql --default-character-set=utf8mb4 -h127.0.0.1 -P3306 -uroot -p123456 xxl_ai < doc/db/patch_20261110_p4_auto_decompose.sql
  mysql --default-character-set=utf8mb4 -h127.0.0.1 -P3306 -uroot -p123456 xxl_ai < doc/db/patch_20261112_feat014_eval.sql
  mysql --default-character-set=utf8mb4 -h127.0.0.1 -P3306 -uroot -p123456 xxl_ai < doc/db/patch_20261112_feat009_workflow.sql
  ```
  > 可执行 `SHOW TABLES LIKE 'xxl_ai_%';` 与 `DESC xxl_ai_agent;` 校验新增表及字段均已就绪。

### 2. 启动基础中间件与双端工程
1. **中间件**：确认本地 MySQL（`3306`）、Redis（`6379`）、Milvus（`19530`，RAG 向量化/检索测试必填）已启动。如需在工作流中联调真实 MCP 工具，可同步启动 `xxl-ai-sample`（端口 `8091`）。
2. **后端 API**：在仓库根目录执行 `mvn -pl xxl-ai-api spring-boot:run`（或在 `xxl-ai-api/` 目录执行 `mvn spring-boot:run`，监听端口 `8080`）。
3. **前端 UI**：在 `xxl-ai-ui/` 目录执行 `npm run dev`（监听端口 `3000`）。
4. **登录系统**：浏览器访问 `http://localhost:3000`，默认账号密码为 `admin / 123456`（测试环境若未关闭验证码可按页面图形验证码输入）。

### 3. 测试前必做的种子数据初始化
> ⚠️ **关键避坑**：[tables_xxl_ai.sql](../doc/db/tables_xxl_ai.sql#L370-L486) 中预设供应商的 `api_key` 均为空，且预设知识库 `三体知识库` 下的 3 篇文档初始状态为 **`未处理`（`status=0`、`chunk_count=0`）**。
1. 进入左侧菜单 **【供应商模型】**，为至少 1 个对话供应商（如 Deepseek、智谱GLM 或本地 Ollama）填入有效 `API密钥` 并确认有可用对话模型（`类型=对话`、`状态=正常`）。
2. 若测试知识库向量化、RAG 评测或真实检索，请确认 **Ollama (`qwen3-embedding:0.6b`)** 已在本地运行（`ollama serve`），或在 **【供应商模型】** 中配置可用的兼容 OpenAI 格式嵌入模型（`类型=嵌入`），并在 **【RAG知识库】** → `三体知识库` 修改页面切换为对应的向量化供应商与模型。
3. 将预设 Agent（如 `Hi Agent`、`SQL优化Agent`）的模型供应商与对话模型调整为你刚刚配置好有效 Key 的模型。

## 一、 [FEAT-014] AI 应用与 RAG 质量量化评测体系测试

本功能提供质量评测中心，支持对 RAG 检索精度（`HitRate@1` / `HitRate@3` / `MRR`）、生成忠实度/相关性及 Agent 目标达成率进行异步批量评测。

### 1.1 评测数据集管理与 JSON 样本导入
> **前置条件**：开始 RAG 评测前，请先确认目标知识库下的文档已完成向量化（`处理状态=已向量化`；若测试 `三体知识库`，请先完成第 [3.1 节](#31-种子文档向量化与-qa-问答对录入) 步骤 1 的全库向量化）。

1. 点击左侧主导航栏：**【质量评测】**（路由 `/#/eval`，位于【供应商模型】下方）。
2. 默认位于 **【评测数据集】** 页签，点击左上方 **【新增】** 按钮：
   - **评测集名称**：填写 `三体知识库基准测试集-01`；
   - **评测类型**：单选 `RAG 知识库检索生成`；
   - **评测目标**：下拉选择 `三体知识库`；
   - **描述说明**：填写 `验证核心人物与关键事件的检索召回精度`；
   - 点击 **【确定】** 保存，列表中新增一条记录，**样本数** 徽标初始显示 `0`。
3. 点击该行操作列中的 **【导入样本】**，弹出 **【导入测试用例样本集 (JSON)】** 对话框（单次最多 50 条）：
   - ⚠️ **数据匹配提示（重要）**：对话框右上角的 **【填入标准示例模板】** 按钮预置的是 XXL-AI 框架问答样本（`expectedDocNames: ["CLOUD_HANDOVER_CONTEXT.md"]`）。**若直接将标准示例模板导入 `三体知识库`，由于文档名与关键词完全不匹配，评测结果命中率将必然为 `0.0%`、`MRR = 0.00`**。
   - **推荐测试方式（二选一）**：
     - **方式 A（继续使用 `三体知识库`）**：手动粘贴以下与 `三体知识库` 种子文档匹配的 JSON 样本：
       ```json
       [
         {
           "id": "santi-001",
           "query": "叶文洁在红岸基地做了什么？",
           "groundTruth": "叶文洁在红岸基地担任工程师，利用太阳增益反射向宇宙发送了地球文明的第一条星际信息。",
           "expectedDocNames": ["主要人物.md", "关键情节.md"],
           "expectedKeywords": ["红岸基地", "星际信息"]
         },
         {
           "id": "santi-002",
           "query": "什么是二向箔？",
           "groundTruth": "二向箔是将三维空间向二维坍缩的降维打击武器，太阳系最终毁于二向箔。",
           "expectedDocNames": ["核心设定.md"],
           "expectedKeywords": ["降维打击", "二维"]
         }
       ]
       ```
     - **方式 B（验证【填入标准示例模板】按钮）**：新建一个知识库，上传仓库内的 [`docs/CLOUD_HANDOVER_CONTEXT.md`](CLOUD_HANDOVER_CONTEXT.md) 并完成向量化，再为该知识库建评测集并点击 **【填入标准示例模板】** 导入。
   - 点击 **【确定】** 保存，表格中 **样本数** 徽标自动更新为 `2`。

---

### 1.2 创建并启动评测实验（异步跑批与手动刷新）
1. 在刚刚导入样本的数据集行，点击操作列中的 **【启动实验】**（播放图标）：
   - **评测集名称**：只读回显数据集名称；
   - **实验名称**：系统已自动生成带时间戳后缀的名称（可按需修改，如 `三体检索基线实验`）；
   - **裁判大模型**：下拉选择可用的对话模型（**说明**：若留空，系统按如下规则回退——对于 `RAG` 评测，回退取当前空间内首个启用态对话模型，并同时承担「答案生成」与「裁判打分」两个角色；对于 `AGENT` 评测，生成阶段始终使用目标 Agent 自身绑定的模型，仅当裁判留空时优先复用目标 Agent 的模型或空间首个启用态对话模型）；
   - 点击 **【立即启动评测】**。
2. 弹窗关闭后，页面自动切换到 **【评测实验中心】** 页签：
   - 列表首行显示新建实验，状态标签为黄色 **【运行中】**；
   - ⚠️ **进度刷新机制说明**：当前页面未启用前端定时轮询（`setInterval`），提交后进度条初始停留在 `0%`。随着后台线程池逐条执行用例，请每隔数秒手动点击上方 **【搜索】** 按钮（或翻页刷新）查看最新进度递增，直到状态变为绿色 **【已完成】**；
   - 完成后，表格行显示平均指标：`命中率 (HitRate@3)`、`倒数排名 (MRR)`、`忠实度 (Faithfulness)`、`答案相关性`。

---

### 1.3 实验报告与逐用例多维指标透视（抽屉面板）
1. 点击该实验操作列的 **【查看报告】**，右侧滑出 **72% 宽度** 的 **【评测实验质量报告与明细透视】** 抽屉：
2. **顶部指标看板**：
   - 核对指标卡片：`命中率 (HitRate@3)`（附子指标 `HitRate@1`）、`倒数排名 (MRR)`、`忠实度 (Faithfulness)`、`答案相关性`、`平均耗时`（卡片下方附累计 `Tokens` 统计；说明：`平均耗时` 与 `Tokens` 仅在报告抽屉中展示，不在列表表格列展示）；
   - 查看 `评测目标参数基线快照:` 蓝色提示栏，确认本次 RAG 实验快照已捕获 `similarityThreshold` 与 `topK`。
3. **用例执行明细折叠面板**：
   - 顶部提供 **`全部` / `仅命中` / `仅未命中`** 单选过滤按钮组；
   - 点击任意用例行展开，逐项核对：
     - **`测试问题:`** 与 **`参考答案:`**；
     - **`检索召回切片:`**：每个切片卡片头部显示 `[文档名称]`（如 `[关键情节.md]`）与 `Score: ...` 相似度标签（注：当前卡片只展示文档名、分数与正文，不展示分片序号）；
     - **`模型生成回答:`**：浅蓝底色框展示 RAG 生成回答；
     - **裁判打分与归因**：淡黄底色评价卡（`.judge-box`），核对 `忠实度`、`答案相关性` 数值及 LLM Judge 输出的评分理由。

---

### 1.4 AGENT 评测与实验取消、删除验证
1. **AGENT 类型评测**：
   - 切回 **【评测数据集】**，点击 **【新增】**，选择评测类型 **`Agent 目标与工具链`**，评测目标选择任意已配置好可用对话模型的 Agent（例如 `SQL优化Agent`）；
   - 导入至少 1 条 JSON 样本（如 `[{"id":"ag-1","query":"请简述深分页 LIMIT 1000000,20 的常见优化思路","groundTruth":"可使用延迟关联或基于主键游标的键集分页替代大偏移量扫描。"}]`）并启动实验；
   - 在实验列表与报告抽屉中，确认 RAG 专属列（`HitRate@3`、`MRR`、`忠实度`）显示为 `-`，**`目标达成率`** 与 **`答案相关性`** 正常计算并给出打分理由。
   - ⚠️ **当前版本能力边界提示**：现阶段 `EvalEngineTool.runAgentCase` 仅基于目标 Agent 的 `系统指令 (systemPrompt)` 进行单轮大模型推理评估，**暂未在评测跑批过程中实际挂载执行 Agent 绑定的 MCP / Skill / SubAgent 工具链或隐式 RAG**（`llmChatTool.chat` 工具参数传入为空数组）。因此暂勿设计强依赖实时联网抓取或 MCP 工具返回结果的 Agent 评测样本。
2. **取消与删除**：
   - 启动一个多样本实验处于 **【运行中】** 时，点击操作列 **【取消】** → 确认后状态变为灰色 **【已取消】**，已跑完的用例结果可在 **【查看报告】** 中查看；
   - 点击实验行或数据集行操作列的 **【删除】**，确认删除功能正常。

## 二、 [FEAT-010] Prompt 动态变量注入与运行参数测试

本功能支持在 Agent 系统指令中通过 **双花括号** `{{变量名}}` 或 `{{变量名:默认值}}` 声明槽位（注意：**不是单花括号 `{var}`**），在公开对话页自动渲染 **【运行参数】** 输入框并随消息实时注入后端渲染。

### 2.1 Agent 配置带双花括号槽位的系统指令
1. 点击左侧一级菜单：**【Agent管理】**（路由 `/#/agent/index`）。
2. 点击 **【新增】**（或选中既有 Agent 点击 **【修改】**），确认模型供应商与对话模型已选择可用配置。
3. 在 **【系统指令】** 输入框中录入包含 `{{...}}` 占位符的模板（故意混合带默认值与不带默认值的两个槽位）：
   ```text
   你是一个专业的数据库优化专家。
   当前待优化的数据库引擎是：{{db_type:MySQL 8.4}}
   业务场景是：{{business_scene}}
   请根据用户后续提供的 SQL 语句，重点关注索引设计与执行计划，输出分步优化建议。
   ```
4. **表单实时解析校验点**：在 **【系统指令】** 输入框正下方，立即出现 **`检测到动态变量:`** 标签栏，分别展示 `{{db_type:MySQL 8.4}}` 与 `{{business_scene}}` 两个灰色胶囊标签。
5. 点击 **【确定】** 保存配置。

---

### 2.2 进入公开对话页与运行参数交互
1. 在 **【Agent管理】** 列表找到刚刚保存的 Agent 行，将 **【发布状态】** 列的开关拨动为 **开启（已发布）**，页面提示 `发布成功`，同时 **【访问URL】** 列出现 **【前往Agent】** 蓝色链接。
2. 点击 **【前往Agent】**，在新标签页打开公开对话页 `/#/chat/{uuid}`（注：列表操作列只有 `修改`、`删除`，无独立的 `调试/对话` 或 `发布` 按钮）。
3. **新对话态（欢迎页内联卡片）**：
   - 画面中央直接展示 **`运行参数`** 卡片（内嵌在居中输入区上方，**不存在独立的弹出抽屉或【确认应用】按钮**）；
   - 检查字段：`db_type` 输入框的占位默认值显示 `MySQL 8.4`，`business_scene` 占位提示为 `请输入变量值`；
   - 在 `db_type` 输入 `MySQL 8.4`（或留空以测试默认值生效），在 `business_scene` 输入 `电商高并发订单分页查询`。
4. 在下方提问框输入 SQL 后按 Enter 发送：

## 四、 [SEC-001 & SEC-002] 安全防线与公网访客沙箱测试

本节验证公网匿名访问对话页时的 HMAC 防篡改令牌防 IDOR 越权机制，以及公网已发布状态下宿主机 `ShellTools` 执行特权剥离。

### 4.1 访客端 HMAC 签名与防 IDOR 越权验证
1. 在 **【Agent管理】** 列表中，确认任一 Agent 的 **【发布状态】** 开关已开启，点击 **【前往Agent】** 打开公开对话页（URL 形如 `http://localhost:3000/#/chat/40bd05136fc34d11b88e1e401d26f50e`），建议在浏览器**无痕窗口**操作。
2. **核对 HMAC 令牌签发机制**：
   - 打开开发者工具（`F12`）→ `Application` → **`Local Storage`**（注意：**存放在 `localStorage`，不是 `sessionStorage`**），确认自动写入两个键：
     - `xxl-ai-agent-visitor`（形如 `v_xxxxxxxx...` 的服务端签发 `visitorId`）
     - `xxl-ai-visitor-token`（服务端响应头 `X-Visitor-Token` 下发的 HMAC-SHA256 签名串，后续前端请求均通过请求头 `X-Visitor-Token` 携带）。
3. **发送消息建立合法会话**：
   - 在无痕窗口发送一条消息（如 `你好`），在 `Network` 面板查看 `/api/chat/session/create` 或 `/api/chat/session/list` 响应，记下刚创建的真实 `sessionId`（例如 `12`）与当前 `visitorId`。
4. **越权攻击复核（防 IDOR）**：
   - 在当前公开对话页的 `DevTools -> Console` 中直接执行以下验证脚本（开发模式下 Vite 将 `/api/*` 代理到后端 `8080`；实际接口路径为 `/chat/session/msgList` 与 `/chat/session/delete`，**不存在 `/chat/msgList` 或 `/chat/convDelete`**）：
   - ⚠️ **响应码说明**：后端所有业务拒绝对请求返回 **HTTP 200**，并通过统一响应体中的业务码 **`code: 500`** 与提示语 `msg` 阻断，**不会返回 HTTP 403 状态码**。
   ```javascript
   const realVisitorId = localStorage.getItem('xxl-ai-agent-visitor');
   const realToken = localStorage.getItem('xxl-ai-visitor-token');

   // 场景1：伪造或篡改 visitorId，但无法伪造匹配的 HMAC 签名
   fetch(`/api/chat/session/msgList?sessionId=12&visitorId=v_tampered_user`, {
     headers: { 'X-Visitor-Token': realToken }
   }).then(r => r.json()).then(d => console.log('篡改visitorId:', d));
   // 预期：{"code":500,"msg":"访客凭证无效或已过期","data":null}

   // 场景2：使用自己合法凭证尝试访问他人（或另一个无痕窗口）的 sessionId
   fetch(`/api/chat/session/msgList?sessionId=1&visitorId=${realVisitorId}`, {
     headers: { 'X-Visitor-Token': realToken }
   }).then(r => r.json()).then(d => console.log('越权查看他人消息:', d));
   // 预期（若 sessionId=1 存在且非本人）：{"code":500,"msg":"无权访问该对话","data":null}

   // 场景3：使用自己合法凭证尝试删除他人会话
   fetch(`/api/chat/session/delete?sessionId=1&visitorId=${realVisitorId}`, {
     headers: { 'X-Visitor-Token': realToken }
   }).then(r => r.json()).then(d => console.log('越权删除他人会话:', d));
   // 预期：{"code":500,"msg":"无权操作该对话","data":null}

   // 场景4：使用未发布 Agent 的 uuid 尝试创建会话（将 UNPUBLISHED_UUID 替换为未发布 Agent 的旧 uuid 或随机字符串）
   fetch(`/api/chat/session/create?uuid=UNPUBLISHED_UUID&visitorId=${realVisitorId}`, {
     headers: { 'X-Visitor-Token': realToken }
   }).then(r => r.json()).then(d => console.log('访问未发布Agent:', d));
   // 预期：{"code":500,"msg":"Agent 不存在或已删除"} 或 {"code":500,"msg":"Agent 未发布，暂不可访问"}
   ```

2. 保存后点击 **【调试试跑】**，将入参修改为 `{"expr": "1+2*3"}`，点击右上角 **【调试试跑】**；

### 5.5 场景五：拓扑安全拦截与反向破坏测试
1. **非法 JSON 拦截**：点击 **【新增】**，在 `DAG 图结构 JSON` 输入缺损文本 `{ "nodes": [ ...`，点击 **【确定】** → 前端直接阻断并提示 `工作流图结构非有效 JSON`。
2. **Kahn 有向环拦截**：保留默认线性模板并在 `edges` 数组末尾追加一条回指环边 `{"id": "e_cycle", "source": "llm_1", "target": "start_1"}`，点击 **【确定】** → 后端 `WorkflowDagEngine.validateGraph` 拦截并提示：
   `工作流拓扑结构校验失败: 工作流拓扑结构存在有向环路 (Cycle Detected)，无法执行！`
3. **孤立节点 / 断链子图 / 条件缺失句柄拦截**：
   - 在 `nodes` 中添加一个无任何连线指向它的节点（如 `{"id": "orphan_1", "name": "孤立", "type": "LLM"}`），保存时拦截报错：`工作流拓扑结构校验失败: 工作流存在孤立节点（无前置连线），无法执行: orphan_1`；
   - 选择条件分支模板并删除其中一条 `cond_1` 出边的 `"sourceHandle"` 字段，保存时拦截报错：`工作流拓扑结构校验失败: 条件节点 [cond_1] 的出边 [...] 必须指定分支标识 (sourceHandle)`。
4. **跨空间知识库 IDOR 运行时阻断**：
   - 新建 RAG 工作流，将 `retrieval_1.config.kbIds` 设为 `[99999]`（不存在或属于其他业务空间的知识库 ID），保存可入库，但点击 **【调试试跑】** 执行时立即失败拦截（`status=2` 失败）：顶部红色横幅 **`执行异常拦截`** 与节点时间轴均提示：
     `RETRIEVAL 节点关联的知识库不存在、已停用或无权访问: kbId=99999`。
5. **停用态工作流拦截**：修改任意工作流将 **状态** 切换为 `已停用` 并保存，点击该行 **【调试试跑】** 中的试跑按钮 → 提示失败 `工作流已停用，无法执行`。

### 5.6 场景六：执行记录筛选、链路追溯与清理
1. **行级快捷跳转**：在 **【工作流列表】** 页签，点击任意工作流操作列的 **【执行记录】**，自动切换至 **【执行记录】** 页签并预填 `工作流ID` 筛选该流程的所有历史 Run。
2. **多条件查询与镜像复现**：
   - 核对表格字段：序号（Run ID）、工作流ID、触发方式（`DEBUG`）、执行状态（`成功` / `失败` / `超时中断`）、总执行耗时、消耗 Token、新增时间；
   - 测试按 **执行状态**（如筛选 `失败`）查询反向测试用例的失败 Run；
   - 点击任意记录的 **【查看链路】**，确认右侧抽屉完整还原当时的入参、错误信息、最终输出及逐节点快照。
3. **执行记录删除**：点击任意历史执行记录操作列的 **【删除】** 并确认，记录成功移除（同时删除工作流时会级联清理其关联执行记录）。
